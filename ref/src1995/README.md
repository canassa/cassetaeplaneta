# The 1995 engine source (reference material)

An early version of the original C++ source of Noite Animal's engine, found on the game
disc. **Never edit these files**: they are an exact unpack of two archives in `assets/`, kept
for reference. `docs/SRC1995.md` has the catalogue, the mapping onto NOITE.EXE and the
behaviour notes; this file is the provenance and the build setup.

## Provenance

| Folder | Archive on the disc | Archive date | Contents |
|---|---|---|---|
| `demog/` | `assets/PAN/WAV/DEMOG.ZIP` (157 KB) | 26 Oct 1995 (entries 25 Oct 1995 00:35-01:51) | 73 entries: 68 `.CPP/.HPP/.C/.H` sources, 5 empty `013942xx` files |
| `ped1/` | `assets/PAN/WAV/PED1.ZIP` (1.1 MB) | 26 Oct 1995 (entries 7 May - 24 Oct 1995) | 110 entries: the engine sources, `.MAK` makefiles, `/Fa` listings (`.ASM`), the build products `DEMO.EXE`, `DEMO.MAP`, `DEMO.BSC`, `DEMO.RES`, `TESTE.EXE`, `TESTE.BSC`, `CASSETA.INI` of 23 Oct, cursors, icon and 35 test bitmaps |

A third archive, `PED2.ZIP`, holds art only and is not unpacked here. The archives were
unpacked with `unzip`, which keeps the upper-case 8.3 names and the stored timestamps. Nothing
was left out.

NOITE.EXE was linked on 28 Feb 1996, four months later, so this is an **ancestor** of its
source, not its exact source. The engine is the same one, though. NE segment 1 (the 32-bit
`FAST_TEXT32` blitters) is byte-identical in DEMO.EXE and NOITE.EXE. Class layouts differ by
a few fields, and the SceneObject vtable has 92 slots here against NOITE's 102.

The developers' project path was `D:\ATR\CASSETA\APLICAT\` (`ATR` is the publisher, ATR
Multimedia). NOITE.EXE still holds the string `d:\atr\casseta\transrle.cpp`, from the same
tree.

## Debug symbols

`ped1/DEMO.EXE` (24 Oct 1995) and `ped1/TESTE.EXE` (20 Oct 1995) are **debug builds with
full CodeView 4 (NB09) information**, and `ped1/DEMO.MAP` is the matching linker map with
line numbers. `tools/cv4dump.py` decodes the CodeView data:

- `symbols.txt` (DEMO.EXE): every module and procedure (address, size, prototype,
  BP-relative parameters and locals with their names), the globals, the publics, and every
  class with its base classes, member offsets and types, and its methods. Virtual methods
  carry their vtable offset.
- `symbols-teste.txt`: the same for TESTE.EXE (READDATA.CPP only).
- `mapping.tsv`: every DEMO.EXE function matched to a NOITE.EXE function, with confidence.
  `docs/SRC1995.md` has the method and the review.

Regenerate the symbol files with
`nix develop -c python3 -I tools/cv4dump.py ref/src1995/ped1/DEMO.EXE "DEMO.EXE (PED1.ZIP, linked 24 Oct 1995)" > ref/src1995/symbols.txt`.

## Build setup (ped1/DEMO.MAK, 24 Oct 1995)

The makefile was generated by MSVC 1.5's Visual Workbench (`ORIGIN = MSVC`), with
`DEBUG = 1` and `PROGTYPE = 0` (a Windows EXE).

| | Debug (used for DEMO.EXE) | Release |
|---|---|---|
| Compiler | `cl /nologo /f- /G3 /FPi87 /Zp4 /W4 /vmg /Zi /AL /Gx- /YX /Od /D_DEBUG /DDEBUG /DSTRICT /DPROFILE /FR /Zn /GA` | `cl /nologo /f- /G3 /FPi87 /Zp4 /W3 /vmg /AS /YX /Od /DNDEBUG /DSTRICT /FR /Zn -Oxwt` |
| Memory model | **large** (`/AL`), 386 code (`/G3`), Windows prolog (`/GA`), struct packing 4 (`/Zp4`), general pointers-to-members with virtual inheritance (`/vmg`) | small (`/AS`; probably a stale setting) |
| Linker | `link /NOE /NOD /STACK:15000 /NOPACKF /ALIGN:16 /CO /MAP /LINE /NOPACKCODE` | `/FARCALL /STACK:65000 ...` |
| Libraries | `libw llibcew wing wintoon oldnames commdlg mmsystem` | `libw slibcew wing wintoon ...` |
| Library paths | `c:\msvc\lib`, `c:\msvc\mfc\lib`, `c:\wing\lib`, `c:\wintoon\lib` | |

- Objects, in link order: TBLT, UTILS, 3DOBJECT, 3DSCREEN, OBJECT, SCREEN, APPLICAT, EVENT,
  CTRPANEL, SCENE, VTREE, GENGAME, GENAPLIC, GENSCENE, READDATA, and `FAST32.OBJ`
  (`OBJS_EXT`). The game-specific files (MSGHANDL, SALA, BARATA, POLAR, CASSETA) are not in
  this makefile. The resources are `DEMO.RES`: the `HAND`/`LEFT`/`RIGHT` cursors and the
  `LIGHTON` icon.
- `DEMO.DEF`: `NAME DEMO`, `DESCRIPTION 'WinG Sprite Demo'`, `EXETYPE WINDOWS`, `CODE
  PRELOAD MOVEABLE`, `DATA PRELOAD MOVEABLE MULTIPLE`, `HEAPSIZE 512`, stub `WINSTUB.EXE`.
- The libraries include WinToon (`wintoon`), Microsoft's cartoon-playback library on top of
  WinG and AVI, although no source here calls it.
- Toolchain consequences for NOITE.EXE: the same compiler (MSVC 1.5x C++), `far pascal`
  methods, `/vmg` virtual inheritance (vbtables, vtordisp thunks), and the WinG sample
  skeleton. NOITE.EXE itself was built **optimised**, with the same `ENTER`/`PUSH DS` prologue
  family. DEMO.EXE is `/Od` and calls `__chkstk` everywhere, so the two never match byte for
  byte.

Other makefiles:

- `ped1/DEMOLC.MAK` (7 May 1995, `PROJPATH = D:\LC\DEMO\`): the first engine. It builds
  DEMO.CPP, TBLT.CPP, UTILS.CPP and GAMEDEFS.CPP plus FAST32.OBJ, small model (`/AS /G2`), and
  writes `/Fa` listings (the `.ASM` files).
- `ped1/TESTE.MAK` (20 Oct 1995): `TESTE.EXE`, a test bed for READDATA.CPP. It is built
  medium model (`/AM /G2 /GA`), debug, and links `mlibcew`.

## How the two archives differ

Both archives hold the same engine. `demog/` is a snapshot made one day after the
`ped1/DEMO.EXE` build.

- **Only in `demog/`**: the game files `MSGHANDL.HPP`, `SALA.CPP/HPP`, `BARATA.CPP`,
  `POLAR.CPP`, `CASSETA.CPP/HPP`, `GAMEPLAY.HPP` and the scene headers `QUARTOZE`,
  `QUARPAIS`, `CORREDOR`, `COZINHA`, `GARAGEM`, `TOMMY`, `ZEMANE` (`.HPP`), plus the five
  empty `013942xx` files.
- **Only in `ped1/`**: the makefiles, the `.ASM` listings (including `FAST32.ASM` and
  `FAST32CP.ASM`), the executables, map and browse files, `CASSETA.INI/BAK`, the art, the
  cursors and the icon.
- **In both, identical**: 3DSCREEN, BGLAYER, DEMO*, EVENT, GAMEDEFS, MECH, OCUPVET, RAY,
  READDATA, RESOURCE, SCREEN, SYSTIMER, TBLT*, TREATCOL, UTILS, VTREE, DIGITALV, MCIAVI.
  The `demog/` copies carry the archiving time (25 Oct 1995 00:35) as their timestamp; the
  `ped1/` copies keep their real dates.
- **In both, `demog/` newer** (every differing file is newer in `demog/`; changed lines in
  brackets):
